# 4. Median of Two Sorted Arrays 

### Problem
Given two sorted arrays nums1 and nums2 of size m and n respectively, return the median of the two sorted arrays.

The overall run time complexity should be O(log (m+n)).

```
Example 1:
Input: nums1 = [1,2], nums2 = [3,4]
Output: 2.50000
Explanation: merged array = [1,2,3,4] and median is (2 + 3) / 2 = 2.5.
```
### Note
To find the median, we only ever need to look at elements up to the middle position — everything past that point doesn't affect the answer. So the loop only runs until index reaches sum/2, instead of walking all the way through both arrays.  
At each step, it picks the smaller of the two current elements (checking array bounds first, so it never reads past the end of either array).  
Once the loop reaches the middle position, it either returns that single middle value directly (odd total length) or adds the last two values together and averages them (even total length).

### Solution
```c
double findMedianSortedArrays(int* nums1, int nums1Size, int* nums2, int nums2Size) {
    int total = 0;
    int sum = (nums1Size+nums2Size);
    int i = 0, j = 0, tmp = 0, index = 0;

    while(index <= sum/2){
        // Check bounds FIRST, before reading the array
        if (j >= nums2Size || (i < nums1Size && nums1[i] <= nums2[j])){
            tmp = nums1[i++];
        }
        else{
            tmp = nums2[j++];
        }

        if(sum % 2 && index == sum/2){
            return tmp;
        }
        else if( !(sum % 2) && (index == sum/2 || index == sum/2 - 1)){
            total += tmp;
        }

        index++;
    }

    return (double)total/2;
}
```
### Problem 1 & Note 1
Problem 1:  
Current complexity:
`O(m+n)`    
Suggested complexity:
`O(log(m+n))`  
Note 1:    
This finds the median in O(log(min(m,n))) by binary searching for a partition point, not by merging the arrays. 
It splits both arrays so the left side holds exactly half the total elements, and searches for the split where every left-side value is <= every right-side value.  
Once that split is found, the median comes directly from the four border values around the cut — the max of the two "left" elements, and for even-length totals, also the min of the two "right" elements, averaged together. 
No merging or full scanning needed.

### Solution 2
```c
int max(int a, int b) { return (a > b) ? a : b; }
int min(int a, int b) { return (a < b) ? a : b; }

double findMedianSortedArrays(int* nums1, int nums1Size, int* nums2, int nums2Size) {
    if (nums1Size > nums2Size) {
        return findMedianSortedArrays(nums2, nums2Size, nums1, nums1Size);
    }
    int m = nums1Size, n = nums2Size;
    int left = 0, right = m;
    while (left <= right) {
        int partitionA = (left + right) / 2;
        int partitionB = (m + n + 1) / 2 - partitionA;
        int maxLeftA = (partitionA == 0) ? INT_MIN : nums1[partitionA - 1];
        int minRightA = (partitionA == m) ? INT_MAX : nums1[partitionA];
        int maxLeftB = (partitionB == 0) ? INT_MIN : nums2[partitionB - 1];
        int minRightB = (partitionB == n) ? INT_MAX : nums2[partitionB];

        if (maxLeftA <= minRightB && maxLeftB <= minRightA) {
            if ((m + n) % 2 == 0) {
                return (max(maxLeftA, maxLeftB) + min(minRightA, minRightB)) / 2.0;
            } else {
                return max(maxLeftA, maxLeftB);
            }
        } else if (maxLeftA > minRightB) {
            right = partitionA - 1;
        } else {
            left = partitionA + 1;
        }
    }
    return 0.0;
}
```
