## L1 — Course Overview

**📘 課前：知識與常識**
這門課接下來 25 講都在圍繞老師的一句核心宣言展開——**「抽象是會漏的」(Abstractions leak)**：你以為 C 幫你擋住了底層（記憶體怎麼配置、CPU 怎麼執行、資料怎麼傳輸），但底層會漏出來咬你，這是整門課存在的理由。第一講老師會現場示範幾個「詭異現象」：同一個數學式子在電腦裡整數會溢位、浮點數不遵守結合律、邏輯完全一樣的程式碼速度可以差到 10 倍。先知道這些例子存在、且它們不是花招而是接下來每一章的伏筆，看第一講時就不會覺得只是在看熱鬧。

**📝 課後：細節與延伸重點**
這一講可以 1.5 倍速，沒有考點，也沒有雷區。真正的功課是：接下來每一講學到新東西時，回頭想一下「這是不是呼應了 L1 提到的哪個詭異現象」——例如 L3 會解釋整數溢位、L4 會解釋浮點不等、L10-L12 會解釋速度差 10 倍怎麼來的。這樣 26 講會串成一條線，而不是 26 個孤立知識點。

## L2 + L3 — Bits, Bytes, and Integers

> 這兩講合起來看。對應 **Data Lab**。

**📘 課前：知識與常識**
這兩講唯一的核心概念：**電腦裡的整數不是數學的整數，它是「模運算下的環」，會繞圈。** 教授接下來所有的推導都是圍繞這句話展開的，帶著它進去聽，會輕鬆很多。

跟著這個概念，教授會頻繁用到三個位元運算「魔法」，最好先認得：
```c
-x  ==  ~x + 1          // 取負 = 取反加一
x >> 31                 // 對 int:正數得 0x00000000,負數得 0xFFFFFFFF
                        // → 這叫「造 mask」,Data Lab 用到爛
!x                      // x==0 時得 1,否則得 0
x ^ y                   // 相同得 0 → 判斷相等神器:!(x^y)
x & (x-1)               // 消掉最低位的 1
```
其中 `x >> 31` 造 mask 這招，教授會拿來示範怎麼在不用 `if` 的情況下模擬條件判斷（Data Lab 硬性規定不准用 `if`）：
```c
// 想要 "if (cond) a else b",cond 是 0 或 1
int mask = ~cond + 1;        // cond=1 → 全1;cond=0 → 全0
result = (mask & a) | (~mask & b);
```

如果一時記不住上面這些式子為什麼成立，先記住這句話，之後就能自己現場推導出來，不用死背：
> **有號數的最高位不是「符號」，而是「一個負的權重」。** 8 位元的二補數 = `-128×b7 + 64×b6 + 32×b5 + ... + 1×b0`。用這個定義去算，所有二補數的性質都自然浮出來。

**📝 課後：細節與延伸重點**

🔥 **雷區一：`unsigned` 是這章唯一的殺手**
老師講二補數會講很久，但真正讓你 debug 到半夜的是有號跟無號混算。C 的規則：兩邊型別不同時，有號會被「靜默」轉成無號。
```c
-1 < 0U        // false!!! 不是 true
               // -1 被轉成 4294967295
```
實戰最常爆的地方（我真的中過）：
```c
for (int i = 0; i < strlen(s) - 1; i++)   // s 是空字串時 → 無窮迴圈
                                          // strlen 回傳 size_t(無號),0-1 變超大數
```
👉 自保法則：看到 `sizeof`、`strlen` 就警覺，迴圈比較的兩邊型別要一致。

🔥 **雷區二：TMin 是個怪物**
```c
int TMin = -2147483648;   // -2^31
-TMin == TMin             // true!!! 取負等於自己
abs(TMin) < 0             // true!!! 絕對值是負的
```
因為正數那邊裝不下 `2147483648`。Data Lab 的測資一定會拿 TMin 陰你，寫完每個函式都拿 TMin 試一次。

🔥 **雷區三：移位超過位數是 undefined behavior**
```c
int x = 1;
x << 32;    // 未定義!x86 實際上只取低 5 位 → 等於 x << 0 → 結果是 1,不是 0
```
Data Lab 有題目就是要你繞過這個限制（不准寫 `>> 32`，要拆成 `>>16 >>16`）。

不用糾結的部分：
- 大端序/小端序（Big/Little Endian）：知道「x86 是小端，低位放低位址」就好，考試偶爾考，實務上很少踩。
- 各種位元運算的數學證明：理解即可，不用背推導。

## L4 — Floating Point

> 這講很多人放棄。**別放棄，它考試一定考，而且 Data Lab 後半段全是它。**

**📘 課前：知識與常識**
這講唯一的核心概念：**浮點數是「用有限位元近似無限小數」，所以它精度有限、間距不均、而且不遵守數學定律。** 後面所有的詭異行為（結合律失效、四捨五入怪怪的）都只是這句話的推論。

教授會用 exp（指數欄位）把浮點數分成三種情況，這是這一講的分類骨架，先認得：

| exp 欄位 | 叫什麼 | 代表什麼 |
|---|---|---|
| 不全 0 也不全 1 | Normalized（規格化） | 一般數字，尾數前面隱含一個 1 |
| 全 0 | Denormalized（非規格化） | 超接近 0 的數 + 0 本身，尾數前面隱含 0 |
| 全 1 | Special | frac 全 0 → 無限大；frac 非 0 → NaN |

為什麼要有 Denormalized？教授一定會解釋：是為了讓數字能平滑地降到 0——沒有它的話，最小的規格化數會直接掉到 0，中間會有一個突兀的大空隙（這叫 gradual underflow）。

如果一時記不住細節，先記住這句話：
> **浮點數在數線上不是均勻分布的——越靠近 0 越密，越遠越稀疏。** 所以大數加小數時，小數會被「吃掉」。理解這件事，後面所有詭異現象都合理了。

**📝 課後：細節與延伸重點**

🔥 **雷區一：`float` 只有 23 位尾數**
```c
int x = 123456789;
float f = x;
(int)f == x       // false!!! 精度掉了
```
`int` 有 32 位有效位，`float` 只有 24 位（23+隱含1）。int → float 會丟精度。但 `int → double` 安全（double 有 53 位）。

考試經典題：下面哪些恆成立？
```c
(float)(double)f == f      // ✅ 真(float 轉大再轉回來沒事)
(double)(float)d == d      // ❌ 假(double 轉小會丟精度)
(int)(float)i == i         // ❌ 假
(int)(double)i == i        // ✅ 真
```

🔥 **雷區二：浮點加法不符合結合律**
```c
(3.14 + 1e20) - 1e20   // 得到 0.0
3.14 + (1e20 - 1e20)   // 得到 3.14
```
這就是為什麼編譯器不敢隨便重排你的浮點運算（L10 會再提到）。

🔥 **雷區三：捨入是「捨入到偶數」(Round-to-even)，不是四捨五入**
```
1.5 → 2    2.5 → 2    3.5 → 4    4.5 → 4
```
不是四捨五入！是「.5 的時候往偶數靠」。為什麼？因為一律進位的話，大量數字加總會系統性偏高。這個一定考。

## L5 — Machine Level Programming I: Basics

> L5–L9 是第一座大山。對應 **Bomb Lab**。

**📘 課前：知識與常識**
先建立心態：**你不需要「會寫」組語，你需要「會讀」。這是完全不同的兩件事，難度差十倍。** 帶著這個心態進去，壓力會小很多。

開始看任何一行組語之前，有三件事一定要先知道，不然教授寫在投影片上的東西你會完全看不懂：

1. **語法方向**：CMU 用 **AT&T 語法**（Linux 預設），跟你網路上查到的 Intel 語法運算元順序相反：
```
AT&T:    movq  %rax, %rbx     意思是 rbx = rax    ← 來源在前
Intel:   mov   rbx, rax       意思是 rbx = rax    ← 目的在前
```
如果你 Google 到一半發現看不懂，先確認你在看哪種語法。我第一週就是被這個搞瘋的。

2. **記憶體定址公式**：看到 `D(Rb, Ri, S)`，它代表的位址是：
```
Mem[ Rb + Ri×S + D ]
```
`D` = 位移常數，`Rb` = 基底暫存器，`Ri` = 索引暫存器，`S` = 縮放（只能是 1/2/4/8）。
例：`8(%rdx, %rcx, 4)` → 位址是 `rdx + rcx*4 + 8`，這一眼就看得出是在存取「元素大小 4 bytes 的陣列」。

3. **指令後綴**：`b`=1 byte, `w`=2, `l`=4（long）, `q`=8（quad）。`movl` = 搬 4 bytes，`movq` = 搬 8 bytes。

**📝 課後：細節與延伸重點**

🔥 **雷區：`leaq` 不碰記憶體**
```asm
movq  8(%rdx), %rax    # 去記憶體位址 (rdx+8) 把「值」拿回來
leaq  8(%rdx), %rax    # 只把「位址 rdx+8」這個數字算出來,不碰記憶體
```
編譯器很愛拿 `leaq` 來做乘法，因為它比 `imul` 快：
```asm
leaq (%rdi,%rdi,2), %rax   # rax = rdi + rdi*2 = rdi*3    ← 這是乘法!
```
Bomb Lab 看到 `leaq` 先想「這是不是在算數學」，不要以為在取位址。

🔥 **隱藏考點：`movl` 會清高 32 位**
```asm
movl  $-1, %eax     # rax 的高 32 位會被「自動清零」
```
寫 32 位暫存器（`%eax`）會把 64 位暫存器（`%rax`）的上半部歸零；但寫 8 位/16 位不會。這個不對稱是考題最愛。

## L6 — Machine Level Programming II: Control

**📘 課前：知識與常識**
這講唯一的核心概念：**你的 `if`/`while`/`for`，在底層全部是「比較 → 條件跳躍」。沒有別的。** 這是讀懂所有控制流組語的鑰匙。

開始讀之前必須先知道兩件事，不然這一整講會全部看不懂：

1. AT&T 語法下，**`cmp a, b` 計算的是 `b - a`，順序是反的**：
```asm
cmpq  %rsi, %rdi      # 這算的是 rdi - rsi (不是 rsi - rdi!)
jg    .L1             # 如果 rdi > rsi 就跳
```
`test a, b` 同理，算的是 `b & a`（常見用法 `testq %rax, %rax` 就是在測 rax 是否為 0）。

2. 跳躍指令對照表：

| 指令 | 條件 | 用於 |
|---|---|---|
| `je` / `jz` | 相等 / 為零 | == |
| `jne` / `jnz` | 不等 | != |
| `jg` `jge` `jl` `jle` | 大於/大等/小於/小等 | 有號數 |
| `ja` `jae` `jb` `jbe` | above/below | 無號數 |

👉 看到 `ja`/`jb` 就知道編譯器把它當無號數在比——這是逆向時判斷變數型別的重要線索。

**📝 課後：細節與延伸重點**

🔥 **全課最容易搞錯的一件事**：`cmp` 順序是反的這件事，我在 Bomb Lab 有一關就是把大小關係搞反，炸了兩次。看到 `cmp`/`test` 先花兩秒確認方向，不要憑直覺讀。

認識「條件搬移」(cmov)：
```asm
cmovg  %rdx, %rax     # 條件成立才搬
```
編譯器在 `if` 兩邊都很短時，會用 `cmov` 取代跳躍，因為分支預測失敗的代價很高（L10 會呼應）。但如果分支裡有「危險運算」（除以零、解參考空指標），編譯器不能用 cmov，因為 cmov 兩邊都會先算。

讀迴圈的訣竅：把組語迴圈翻回 C，一律先翻成 `do-while`，再判斷是不是 `while`/`for`。因為編譯器產生的迴圈骨架就是 do-while（先做一次，尾巴判斷跳回去）——這是做 Bomb Lab 時最實用的一個技巧。

## L7 — Machine Level Programming III: Procedures

> **這講是 Bomb Lab 的核心。認真看。**

**📘 課前：知識與常識**
這講唯一的核心概念：**函式呼叫 = 一套「大家都同意遵守」的規矩（呼叫慣例），讓不同人寫的程式碼能接得起來。** 教授會逐一講解這套規矩的三個部分，先預習過一遍，上課會輕鬆很多。

**參數順序**（背下來，Bomb Lab 天天用）：
```
第1個參數 → %rdi
第2個參數 → %rsi
第3個參數 → %rdx
第4個參數 → %rcx
第5個參數 → %r8
第6個參數 → %r9
第7個以後 → 壓進堆疊
回傳值   → %rax
```
記憶法：di-si-d-c-8-9（「弟media洗底 c 八九」隨你編）。

**誰負責保存暫存器**：

| 類型 | 暫存器 | 意思 |
|---|---|---|
| Caller-saved（呼叫者保存） | `%rax %rcx %rdx %rsi %rdi %r8-%r11` | 被呼叫的函式可以隨便用，你自己要先存好 |
| Callee-saved（被呼叫者保存） | `%rbx %rbp %r12 %r13 %r14 %r15` | 函式想用就得先 push，回去前要 pop 還原 |

👉 當你在組語裡看到函式開頭 `pushq %rbx`，結尾 `popq %rbx`，那就是 callee-saved 的規矩，不用去猜它在幹嘛。

**堆疊往「低位址」長**：
```
高位址
  ↑   [ 舊的 frame ]
      [ 返回位址   ]   ← call 自動壓入
      [ 儲存的暫存器 ]
      [ 區域變數   ]
  ↓   ← %rsp 指這裡(堆疊頂端)
低位址
```
`pushq` = `rsp` 減 8，再寫入 → 堆疊變大是位址變小。
`call` = 把「下一條指令的位址」壓入堆疊，然後跳。
`ret` = 從堆疊彈出位址，跳回去。

**📝 課後：細節與延伸重點**

👉 Bomb Lab 裡 push/pop 佔了組語裡一大堆行，認出來是 callee-saved 的規矩就能直接跳過，不用逐行細看。

🔥 **雷區：`subq $32, %rsp` 是在幹嘛？**
函式一開頭常看到這行——這是在「開闢區域變數空間」，不是在做減法。看到就知道「這函式有大約 32 bytes 的區域變數」。

`ret` 的行為就是「彈出堆疊頂端的值當作位址跳過去」——記住這句，L9 的緩衝區溢位攻擊你會秒懂：如果堆疊上返回位址那格被你寫壞的資料蓋掉，`ret` 就會跳到你指定的地方。

## L8 — Machine Level Programming IV: Data

**📘 課前：知識與常識**
這一講在講**資料在記憶體裡怎麼被安排**——陣列、struct、指標型別的位址怎麼算，是連接 L7（堆疊結構）跟 L9（緩衝區溢位攻擊）的橋樑知識。

**陣列位址公式**：
```c
int A[N];
A[i]  的位址 = A + 4*i
```
二維：
```c
int D[R][C];
D[i][j] 的位址 = D + 4*(C*i + j)     // 注意是 C(行寬),不是 R
```

**Struct 對齊規則**（必背兩條）：
1. 每個成員的位址，必須是「該成員大小」的倍數。
2. 結構體整體大小，必須是「最大成員大小」的倍數（所以尾巴也可能補空）。

**陣列指標 vs 指標陣列**（開始讀組語裡的宣告前要先分得清）：
```c
int *A[10];    // 指標陣列:10 個 int*  (大小 80)
int (*A)[10];  // 陣列指標:1 個指向「10 個 int」的指標 (大小 8)
```
口訣：看括號，有括號先結合括號。

**Union 的用途**：`union` 所有成員共用同一塊記憶體，大小 = 最大成員。用途是「同一塊 bits 用兩種方式解讀」：
```c
union { float f; unsigned u; } x;
x.f = 3.14;
printf("%x", x.u);   // 印出 float 的位元長相
```

**📝 課後：細節與延伸重點**

🔥 **雷區：結構體的大小不等於成員大小總和**
```c
struct S1 {          struct S2 {        // 一樣的成員,不同順序
    char c;              int  i;
    int  i;              char c;
    char d;              char d;
};  // 大小 12!          };  // 大小 8
```
一樣的成員，只是換個順序，大小就差了 4 bytes。👉 實務結論：把大的成員放前面，小的放後面，可以省記憶體。這是面試常考題。

👉 逆向技巧：看到 `imul $C, %rdi` 這種乘一個奇怪常數，那個常數通常就是二維陣列的行寬——這是做 Bomb Lab 逆向組語時判斷「這是不是在存取二維陣列」的線索。

## L9 — Machine Level Programming V: Advanced Topics

> 對應 **Attack Lab**。這講是全課最爽的一講。

**📘 課前：知識與常識**
這講唯一的核心概念：**因為「返回位址」跟「你的區域變數」放在同一個堆疊上（見 L7 的堆疊圖），所以陣列寫爆就能劫持程式流程。**

攻擊原理（三句話講完）：
1. 你的 `char buf[8]` 在堆疊上，返回位址就在它上面幾格。
2. 用 `gets()` 這種不檢查長度的函式，可以一直往上寫。
3. 把返回位址蓋成你想跳的地方 → `ret` 執行時就跳過去了（見 L7：`ret` = 彈出堆疊頂端當位址跳過去）。
```c
void foo() {
    char buf[8];
    gets(buf);      // ← 兇手就是它。永遠不要用 gets
}
```

教授會講三道防線，這是這一講的教學主軸，先認得它們防什麼：

| 防禦 | 怎麼做 | 擋掉什麼 |
|---|---|---|
| Stack Canary（金絲雀） | 在 buf 和返回位址之間放一個隨機值，返回前檢查有沒有被改 | 擋掉「連續覆蓋」 |
| NX / 不可執行堆疊 | 把堆疊標成不可執行 | 擋掉「注入自己的機器碼」 |
| ASLR（位址隨機化） | 每次執行堆疊位址都不同 | 擋掉「寫死跳躍位址」 |

**📝 課後：細節與延伸重點**

為什麼還是擋不住？→ **ROP**。既然不能注入新程式碼，那就用程式裡「原本就有的」片段。找一堆結尾是 `ret` 的小片段（叫 gadget），把它們的位址一個接一個排在堆疊上，`ret` 就會像串珠子一樣一個一個執行。這叫 **ROP（Return-Oriented Programming）**，是 Attack Lab 的 Phase 4-5。
👉 做 Attack Lab 的訣竅：先把 `ret` 的機器碼 `c3` 記起來，用它在 dump 裡搜 gadget。

順帶一提：為什麼 C 這麼危險——C 不做陣列邊界檢查。這是速度的代價。Java/Python 會檢查，所以沒這問題（但慢）。這就是老師常說的「C 給你全部的權力，也給你全部的責任」。

## L10 — Program Optimization

**📘 課前：知識與常識**
這講唯一的核心概念：**編譯器很聰明，但它「不敢」做任何可能改變結果的優化。你的工作是把它的顧慮拿掉。**

**編譯器最大的顧慮：記憶體別名 (Memory Aliasing)**
```c
void twiddle(long *xp, long *yp) {
    *xp += *yp;
    *xp += *yp;
}
```
你以為可以優化成 `*xp += 2 * *yp`？編譯器不敢。因為如果 `xp == yp`，兩者結果不同（前者變 4 倍，後者變 3 倍）。你能做的：用區域變數把值先讀出來，等於跟編譯器保證「這裡沒有別名問題」：
```c
long t = *yp;        // 讀一次
*xp += 2 * t;
```

**最經典的效能地雷：迴圈裡呼叫 `strlen`**
```c
for (i = 0; i < strlen(s); i++)   // ❌ strlen 是 O(n),整體變 O(n²)
```
編譯器不敢把 `strlen(s)` 提出迴圈（它不知道迴圈裡會不會改到 `s`）：
```c
size_t len = strlen(s);           // ✅ 自己提出來
for (i = 0; i < len; i++)
```
這是老師課上的招牌 demo，字串一長效能差幾百倍。

三個真的有用的手動優化：
1. 把迴圈不變的計算搬出去（code motion）
2. 減少記憶體讀寫，改用區域變數累加（因為記憶體比暫存器慢太多）
3. 多累加器 + 迴圈展開：因為 CPU 能同時做好幾件事（ILP），用一個累加器會被「依賴鏈」卡住
```c
// 單累加器:每次都要等上一次算完
for (i=0; i<n; i++) acc = acc * a[i];

// 雙累加器:兩條線並行,速度接近 2 倍
for (i=0; i<n-1; i+=2) { acc0 = acc0*a[i]; acc1 = acc1*a[i+1]; }
```

分支預測：現代 CPU 會猜 `if` 走哪邊，猜錯要付出 ~15-20 週期的代價。規律的分支（例如迴圈邊界）幾乎零成本；隨機的分支（例如 `if (data[i] > 128)` 而 data 是亂數）才是災難。

**📝 課後：細節與延伸重點**

學長的優化鐵則：
> **先量測，再優化。** 不要憑感覺猜哪裡慢，人類的直覺在這件事上準確率極低。而且：**先確保程式是對的**，一個快但錯的程式價值是零。

## L11 — The Memory Hierarchy

**📘 課前：知識與常識**
這講唯一的核心概念：**快的記憶體很貴很小，便宜的很慢很大。所以做成金字塔，靠「區域性」讓資料盡量待在上層。**

數量級（有感覺就好，不用背精確值）：

| 層級 | 存取時間 | 比喻（如果暫存器是 1 秒） |
|---|---|---|
| 暫存器 | ~0 週期 | 1 秒 |
| L1 快取 | ~4 週期 | 4 秒 |
| L2 快取 | ~10 週期 | 10 秒 |
| L3 快取 | ~40 週期 | 40 秒 |
| 主記憶體 | ~200 週期 | 3 分鐘 |
| SSD | ~100,000 週期 | 1 天 |
| 硬碟 | ~10,000,000 週期 | 4 個月 |

👉 看懂這張表就懂為什麼「省記憶體存取」比「省 CPU 運算」重要得多。

兩種區域性：
- 時間區域性：剛用過的東西，馬上會再用 → 迴圈變數。
- 空間區域性：用了 `a[i]`，接下來很可能用 `a[i+1]` → 順序掃陣列。

判斷「這段程式區域性好不好」的訣竅：看記憶體存取的「步長 (stride)」：
```c
for (i=0; i<N; i++) sum += a[i];        // stride-1 → 空間區域性極佳 ✅
for (i=0; i<N; i+=16) sum += a[i];      // stride-16 → 每次都跳過整個 cache line ❌
```

教授一定會用這個例子考你：**二維陣列的迴圈順序**
```c
// C 語言是「列優先 (row-major)」,同一列在記憶體裡是連續的
for (i...) for (j...) sum += a[i][j];   // ✅ 快(順著記憶體走)
for (j...) for (i...) sum += a[i][j];   // ❌ 慢(每次跳一整列)
```
只是換個迴圈順序，速度可以差 10 倍以上。這是整門課最實用的一個結論，一定要能自己講出「為什麼」。

**📝 課後：細節與延伸重點**
這一講本身沒有太多雷，它是 L12 Cache 的鋪墊。真正的雷（set index、conflict miss）會在下一講的 Cache Lab 具體踩到，這裡先把「區域性」的直覺建立好就足夠。

## L12 — Cache Memories

> 對應 **Cache Lab**。這講很硬，但撐過去 Cache Lab 就通了。

**📘 課前：知識與常識**
這一講在講**硬體怎麼決定一筆資料該放進快取的哪個位置**，這是 Cache Lab 整份規格書的理論基礎。

必背三個參數 S / E / B：
```
S = Set 數量(組)      → 用位址中間的位元選
E = 每組幾條 line     → E=1 叫直接映射,E=全部叫全關聯
B = 每條 line 幾 bytes → 用位址最低位元選 offset
```
位址被切成三段：
```
[  Tag  ][ Set index ][ Block offset ]
   高位       中間           低位
```

教授會花很多時間解釋**為什麼 Set index 用「中間」的位元，不用高位**：如果用高位當索引，那麼連續的記憶體位址會全部擠進同一組，一個順序掃描的陣列會瘋狂互踢（conflict miss），空間區域性完全被浪費。用中間位元，連續的區塊才會平均散到各組——這題我期中考過，是這一講最核心的推理，務必聽懂而不是背答案。

三種 Miss：

| 種類 | 原因 | 能不能避免 |
|---|---|---|
| Cold miss（強制） | 第一次存取，快取是空的 | 不能，無可避免 |
| Conflict miss（衝突） | 明明還有空位，但都映射到同一組 | 能，改資料佈局 |
| Capacity miss（容量） | 工作集比快取還大 | 能，用分塊 |

**📝 課後：細節與延伸重點**

🔥 **最惡毒的雷：步長是 2 的次方**
```c
// 陣列大小剛好是 2 的次方時,災難
int a[256][256];
for (i=0; i<256; i++) sum += a[i][0];   // 每次跳 1024 bytes
```
因為 set index 取的是中間位元，跳的距離剛好是 2 的次方時，會全部落在同一組，直接映射的快取就一直互踢。
👉 這就是 Cache Lab Part B「32×32 矩陣轉置」最痛的地方：對角線元素 `A[i][i]` 和 `B[i][i]` 會映射到同一組，一直互相踢掉。解法：用區域變數一次讀 8 個元素暫存起來，避開衝突。這招學會了 Cache Lab 就過了一半。

分塊 (Blocking) — Cache Lab 的核心技巧：不要一次處理整個大矩陣，切成小塊，讓每一小塊剛好塞得進快取：
```c
for (ii=0; ii<n; ii+=B)          // B 通常取 8
  for (jj=0; jj<n; jj+=B)
    for (i=ii; i<ii+B; i++)
      for (j=jj; j<jj+B; j++)
        ...
```

學長的建議：Cache Lab Part A（寫快取模擬器）不難，照著規格寫就好。時間全部留給 Part B。而且 Part B 的 32×32、64×64、61×67 三個 case 解法完全不同，64×64 要用「4×4 分塊 + 暫存」的騷操作，做好心理準備。

## L13 — Linking

**📘 課前：知識與常識**
這講唯一的核心概念：**你的 `#include` 只是複製貼上宣告。真正把不同 `.c` 檔「接起來」的是連結器。**

編譯全流程：
```
hello.c  --前置處理(cpp)-->  hello.i   （展開 #include、巨集）
         --編譯(cc1)------>  hello.s   （組合語言）
         --組譯(as)-------->  hello.o  （可重定位目標檔）
         --連結(ld)-------->  hello    （可執行檔）
```

教授會講**強符號 / 弱符號規則**，這是這一講的核心教學內容，三條規則先背起來：
1. 不准有兩個強符號同名 → 直接連結錯誤（這個還算好）。
2. 一強一弱 → 選強的，弱的被靜默忽略 ⚠️。
3. 兩個都弱 → 隨便選一個 ⚠️⚠️。

強符號 = 函式、已初始化的全域變數；弱符號 = 未初始化的全域變數。

標頭檔只放宣告（`extern int global;`、函式原型），不放定義：
```c
// foo.h
int global = 0;        // ❌ 每個 include 它的 .c 都會產生一個定義
void bar() { ... }     // ❌ 同上
```

**📝 課後：細節與延伸重點**

🔥 **全課最陰險的雷**：強弱符號規則為什麼可怕？看這個例子：
```c
/* a.c */                      /* b.c */
int x = 5;                     double x;      // 未初始化 → 弱符號
int main() { ... }             void f() { x = 3.14; }
```
編譯完全沒有錯誤和警告。但 `b.c` 寫入 8 bytes，`a.c` 只有 4 bytes → 記憶體被踩爛，程式在完全無關的地方崩潰。

👉 自保法則（這條救過我很多次）：
- 全域變數一律加 `static`（除非真的要跨檔案用）。
- 編譯永遠開 `-Wall -Werror`。

🔥 **雷：靜態函式庫的連結「順序有關」**
```bash
gcc main.o -lm           # ✅ 對
gcc -lm main.o           # ❌ 可能報 undefined reference
```
連結器是從左到右掃一次，掃到函式庫時只挑「目前還缺的符號」。如果函式庫排在前面，那時候還不知道缺什麼，就什麼都不挑。規則：函式庫放最後面。互相依賴的話甚至要重複寫兩次。

標頭檔放定義是新手最常犯的錯，通常是因為圖方便，結果每個 include 它的 `.c` 都各自產生一份定義，連結時才爆炸。

## L14 — Exceptional Control Flow: Exceptions and Processes

**📘 課前：知識與常識**
這講唯一的核心概念：**作業系統怎麼製造出「每個程式都獨佔一台電腦」的幻覺。**

必背四種異常（教授會逐一比較它們的差異，考試常考）：

| 類型 | 誰觸發 | 同步/非同步 | 返回到哪 |
|---|---|---|---|
| Interrupt（中斷） | 外部裝置（鍵盤、計時器） | 非同步 | 下一條指令 |
| Trap（陷阱） | 程式主動（系統呼叫） | 同步 | 下一條指令 |
| Fault（故障） | 出錯但可能修復（缺頁） | 同步 | 重新執行同一條指令 |
| Abort（中止） | 不可修復錯誤 | 同步 | 不返回，程式死 |

行程 (Process) 給你的兩個幻覺：
- 獨佔 CPU：其實是快速切換（context switch）。
- 獨佔記憶體：其實是虛擬記憶體（L17 詳講）。

三個狀態：Running / Stopped（被 signal 暫停）/ Terminated。

**📝 課後：細節與延伸重點**
👉 上表最後一欄要特別記牢：「缺頁 (Page Fault) 處理完會重新執行同一條指令」這件事是 L17 虛擬記憶體的關鍵前提，到時候會直接用到，不要學完就忘。

## L15 — ECF: Signals and Nonlocal Jumps

> 對應 **Shell Lab**。**這是全課雷最多的一講，慢慢看。**

**📘 課前：知識與常識**
`fork()` 會產生一個新行程，`signal` 是行程之間非同步的通知機制——這兩個東西各自不難，但**組合在一起時的時序 (timing) 問題**才是這一講真正的難點。教授會講清楚 `fork` 的基本行為：

```c
pid_t pid = fork();
if (pid == 0) { /* 子行程 */ }
else          { /* 父行程,pid 是子的 PID */ }
```
- `fork` 會**回傳兩次**：一次在父行程（回傳子的 PID），一次在子行程（回傳 0）。
- 父子執行順序**完全不確定**，由排程器決定。

僵屍與孤兒（教授會定義這兩個名詞）：
- 僵屍行程 (Zombie)：子行程死了，但父行程沒 `wait` → 屍體卡在系統裡。
- 孤兒行程：父行程先死 → 子行程被 init（PID 1）接收，由它回收。

**📝 課後：細節與延伸重點**

🔥 **坑：`printf` 的緩衝區也會被複製**
```c
printf("hello");    // 沒有 \n,還在緩衝區裡
fork();             // 緩衝區被複製了 → "hello" 會被印兩次!
```
👉 自保：`fork` 前先 `fflush(stdout)`，或永遠記得加 `\n`。

🔥🔥 **Shell Lab 最大的雷：訊號不排隊！**
訊號只有「有」和「沒有」兩種狀態，沒有計數器。如果 3 個子行程同時結束，送來 3 個 `SIGCHLD`，你的 handler 可能只被呼叫 1 次。
👉 正確寫法：handler 裡要用 `while` 迴圈把「所有」結束的子行程都收乾淨：
```c
void sigchld_handler(int sig) {
    int olderrno = errno;                        // ① 存 errno
    while (waitpid(-1, NULL, WNOHANG) > 0)       // ② while 不是 if!WNOHANG 不阻塞
        ;
    errno = olderrno;                            // ③ 還原 errno
}
```
這段程式碼我建議你直接背下來。三個細節缺一不可，是 Shell Lab 的送分/送命題。Shell Lab 一定要正確回收子行程，不然跑一跑系統就爆炸。

🔥 **雷：handler 裡不能用 `printf`**
Handler 只能呼叫 async-signal-safe 的函式。`printf`、`malloc` 都不安全（它們有內部狀態，被中斷會壞掉）。CSAPP 給你 `Sio_puts()` / `sio_putl()` 這種安全版本，handler 裡只能用這些。（除錯時偷用 printf 通常不會當場爆，但那是運氣，別依賴。）

🔥 **雷：經典的競爭條件 (Race)**
```c
pid = fork();
if (pid == 0) execve(...);
addjob(pid);            // ⚠️ 如果子行程「秒結束」,SIGCHLD handler 可能
                        //     在 addjob 之前就跑了 deletejob → job 永遠刪不掉
```
👉 解法：`fork` 之前先用 `sigprocmask` 把 `SIGCHLD` 擋住，`addjob` 完再解除。（記得在子行程裡 `execve` 前要把訊號遮罩解開，因為遮罩會被繼承——這又是一個小雷。）

## L16 — System Level I/O

**📘 課前：知識與常識**
核心觀念：**「一切皆檔案」**——鍵盤、螢幕、網路連線，在 Unix 眼裡都是檔案，都用 `read`/`write` 操作。檔案描述符是個小整數：`0`=stdin，`1`=stdout，`2`=stderr。這講可以稍微放鬆看。

教授會強調一個違反直覺的事實：**Short Count（讀不滿）**
```c
read(fd, buf, 100);    // 要求讀 100 bytes,可能只回傳 40!
```
這不是錯誤，是正常行為。發生在：讀到檔案結尾、從終端機讀、從網路 socket 讀。所以 CSAPP 提供 RIO 套件（`rio_readn` / `rio_writen`），它內部用迴圈確保讀滿，這是這一講的重點工具，先知道它為什麼存在。

**📝 課後：細節與延伸重點**

🔥 **雷：RIO 的兩種版本不能混用**
- `rio_readn` / `rio_writen` — 無緩衝，用於二進位資料。
- `rio_readlineb` / `rio_readnb` — 有緩衝，用於讀文字行。
同一個 fd 上，不要混用有緩衝和無緩衝的版本（緩衝區會偷偷多讀資料，導致無緩衝那邊讀不到）。Proxy Lab 的正確做法：讀 HTTP 標頭用 `rio_readlineb`，讀 body 用 `rio_readnb`（同樣是緩衝版）。Proxy Lab 一定要用 RIO，直接用 `read` 保證出事。

什麼時候不要用系統呼叫：`read`/`write` 每次都要進核心，很貴。一般讀檔案用標準 I/O（`fopen`/`fscanf`）就好，它有緩衝。只有網路 socket 才建議用 RIO（因為標準 I/O 在 socket 上有些詭異限制）。

## L17 — Virtual Memory: Concepts

> **全課第二座大山（第一座是組語）。這講抽象，但一旦通了會很爽。**

**📘 課前：知識與常識**
這講唯一的核心概念：**你程式看到的位址全部是假的。CPU 裡有個硬體 (MMU) 偷偷把假位址翻譯成真位址。**

為什麼要這樣搞？教授會講三個好處，先認得：
1. 快取：把主記憶體當成硬碟的快取 → 你能用比實體記憶體更大的空間。
2. 記憶體管理：每個行程都以為自己從 0 開始有一整片連續空間 → 編譯器和連結器超好寫。
3. 保護：每個頁表項有權限位元 → 行程之間踩不到彼此，使用者踩不到核心。

位址翻譯的拆法：
```
虛擬位址 VA = [  VPN (虛擬頁號)  ][ VPO (頁內偏移) ]
實體位址 PA = [  PPN (實體頁號)  ][ PPO (頁內偏移) ]
                     ↑ 靠頁表翻譯      ↑ 直接複製,完全不變!
```
這一句是理解全章的鑰匙：
> **VPO 和 PPO 是一模一樣的，直接抄過去，不需要翻譯。** 因為頁的大小是固定的（例如 4KB），頁內的偏移量在虛擬和實體都一樣，只需要翻譯「頁號」那一段。推論：頁大小 4KB = 2^12 → VPO 就是低 12 位，剩下的都是 VPN。

缺頁 (Page Fault) 的完整流程（教授會按順序講，考試常考順序）：
1. CPU 給虛擬位址 → MMU 查頁表。
2. 發現有效位是 0（頁不在實體記憶體裡）→ 觸發 Page Fault 例外。
3. 核心的處理程式接手：選一個犧牲頁換出去、從硬碟把要的頁載入。
4. 更新頁表。
5. 返回，重新執行剛剛那條指令 ← 這次就成功了（呼應 L14 的 Fault 類型異常）。

**📝 課後：細節與延伸重點**
一個常見誤解：「頁表在哪裡？」→ 頁表本身也在主記憶體裡。所以每次記憶體存取，理論上要查兩次記憶體（一次查頁表、一次拿資料）。這太慢了，所以有 TLB（下一講）。

## L18 — Virtual Memory: Systems

**📘 課前：知識與常識**
這講是上一講的「實作細節版」：L17 講「為什麼有虛擬記憶體」，這講講「硬體/OS 具體怎麼把翻譯做快、把頁表做小」。

**TLB — 頁表的快取**：TLB 就是一個專門存「VPN → PPN」對照的小快取，在 MMU 裡面。命中的話翻譯是零成本；沒命中才去查記憶體裡的頁表。TLB 的位址切法（考試會叫你算）：
```
VPN 再切成:[ TLB tag ][ TLB index ]
```
跟 L12 的快取切法完全一樣的道理。

**多層頁表 — 為什麼需要**：單層頁表的問題：64 位系統，如果做一張完整的頁表，大到荒謬（2^52 個項目 × 8 bytes = 天文數字）。多層的解法：大部分的位址空間是空的，如果第一層某個項目是空的，底下整棵子樹都不用建。一句話：多層頁表省的是「空洞」的空間。

必背：Linux 行程記憶體佈局圖（畫得出來就贏了）
```
高位址  ┌──────────────┐
        │  核心區(不可存取)│
        ├──────────────┤
        │   Stack ↓     │  ← 區域變數、函式呼叫框架
        │      ...      │
        │   共享函式庫   │  ← libc.so 等,mmap 映射進來
        │      ...      │
        │   Heap ↑      │  ← malloc 拿的地方,往上長
        ├──────────────┤
        │  .data/.bss   │  ← 全域變數
        │    .text      │  ← 程式碼(唯讀)
低位址  └──────────────┘
```
Stack 往下長、Heap 往上長，中間留給共享函式庫——這張圖串起了 L7（堆疊）、L13（連結）、L19（malloc），務必記住。

**📝 課後：細節與延伸重點**

兩個很酷的應用（理解了會覺得 VM 很美）：
1. `fork` 為什麼這麼快？→ 寫入時複製 (Copy-on-Write)。`fork` 不真的複製記憶體，只複製頁表，並把所有頁標成「唯讀」。只有當某一方真的要「寫入」時，才觸發保護錯誤，那時才真的複製那一頁。👉 這就是為什麼 `fork` 之後馬上 `execve` 幾乎沒有成本。
2. `mmap`：把檔案「映射」成記憶體，你直接用指標讀檔案內容，不用 `read`。共享函式庫、`fork`、`malloc` 底層全都靠它。

## L19 — Dynamic Memory Allocation: Basic Concepts

> 對應 **Malloc Lab**。**公認全課最硬的 Lab，預留兩倍時間。**

**📘 課前：知識與常識**
這講唯一的核心概念：**`malloc` 不是魔法，它是一個在「堆積」上維護空閒清單的記帳程式。你要自己寫一個。**

兩種碎片：
- 內部碎片：給你的區塊比你要的大（因為對齊、因為要放標頭）→ 浪費在區塊「裡面」，你當下就知道多少。
- 外部碎片：總空閒空間夠，但被切得太散，湊不出一塊連續的 → 浪費在區塊「之間」，要看未來的請求才知道，更難對付。

核心技巧：**標頭 + 腳部 (Boundary Tag)**。問題：`free(p)` 的時候，怎麼知道這塊多大？怎麼知道「前一塊」是不是空的？解法：
- 每塊前面放一個 header 存「大小 + 是否已配置」→ 解決「多大」。
- 每塊後面再放一個 footer（內容跟 header 一樣）→ 解決「往前合併」，往前退 8 bytes 就能讀到「前一塊的 footer」，立刻知道前一塊的大小和狀態。
```
[ header ][      payload      ][ footer ]
   4/8B      使用者拿到的指標       4/8B
```

騷操作：因為所有區塊都是 8（或 16）位元組對齊，大小的低 3 位一定是 0，那三個位元就空著沒用，把「是否已配置」塞進最低位：
```c
size_t header = size | alloc;        // 打包
size_t size  = header & ~0x7;        // 取大小(遮掉低 3 位)
int    alloc = header & 0x1;         // 取標記
```
Malloc Lab 從頭到尾都在做這件事，這幾行等於是 Lab 的通關密語。

三種找空位的策略：

| 策略 | 做法 | 取捨 |
|---|---|---|
| First fit | 從頭找，第一個夠大的就用 | 快，但開頭會累積小碎片 |
| Next fit | 從上次停的地方繼續找 | 更快，但碎片更嚴重 |
| Best fit | 找遍全部，挑最接近的 | 利用率最好，但最慢 |

**📝 課後：細節與延伸重點**
這些技巧全部會直接用在 Malloc Lab，實際動手寫的時候才會真的體會「為什麼 header/footer 要這樣設計」。卡關時回來重看 header+footer 那段圖，通常就是忘了某個 offset。

## L20 — Dynamic Memory Allocation: Advanced Concepts

**📘 課前：知識與常識**
這講講的是 **malloc 實作的三種進化路線**，是 Malloc Lab 從及格到高分的具體施工順序：
```
① 隱式空閒鏈結串列 (Implicit)   → 靠 header 的大小欄位一塊塊跳
                                   簡單,但找空位是 O(全部區塊) 很慢
                                   ↓
② 顯式空閒鏈結串列 (Explicit)   → 在「空閒區塊的 payload 裡」存前後指標
                                   只走空閒的,快很多 ⭐ 建議至少做到這裡
                                   ↓
③ 分離空閒串列 (Segregated)     → 按大小分好幾條串列(16-32, 33-64, ...)
                                   接近 glibc 的真實做法,拿高分靠它
```
② 的關鍵洞察：空閒區塊的 payload 反正沒人用，那塊空間拿來存指標是免費的。這個想法很聰明，自己想不出來很正常。

必做：**合併 (Coalescing)**。`free` 之後一定要跟相鄰的空閒塊合併，不然外部碎片會炸掉。四種情況：
```
前空後空 → 三塊合一    前空後滿 → 往前合
前滿後空 → 往後合      前滿後滿 → 不動
```
寫成一個 `coalesce()` 函式處理這四種 case，是 Malloc Lab 的標準骨架。

記憶體 bug 三兄弟（面試也常問，教授會定義這三個名詞）：

| Bug | 症狀 |
|---|---|
| Memory Leak | 忘記 free，程式越跑吃越多記憶體 |
| Dangling Pointer | free 之後還用那個指標 → 讀到垃圾或崩潰 |
| Double Free | free 兩次 → 破壞配置器內部結構，通常在很久之後才崩 |

**📝 課後：細節與延伸重點**

🔥 **Malloc Lab 的四大死法（我全中過）**
1. 指標運算沒轉型——`(char *)p + 8` 才是「往後 8 bytes」；`(int *)p + 8` 是往後 32 bytes！👉 所有指標運算一律先轉成 `char *`。
2. 對齊沒做對——必須 16 bytes 對齊。`ALIGN(size)` 巨集一定要用。
3. 忘記更新 footer——改了 header 沒改 footer，合併時就爆炸。
4. 邊界處理——堆積頭尾要放「哨兵區塊」(prologue/epilogue)，否則合併時會走出界。

👉 強烈建議：一開始就寫一個 `mm_checkheap()` 檢查函式，遍歷整個堆積驗證所有不變量（對齊對不對、header=footer 嗎、有沒有兩個相鄰的空閒塊沒合併）。看起來浪費時間，實際上會省你十倍時間。這是這個 Lab 唯一的活路，講義也會這樣講，請務必聽話。

最可怕的是記憶體 bug 的「症狀出現地點」跟「真正錯誤地點」通常差很遠。這就是 C 語言最折磨人的地方，也是為什麼要學 `valgrind`。

## L21 + L22 — Network Programming

> 對應 **Proxy Lab**。這兩講比前面輕鬆，而且做完很有成就感。

**📘 課前：知識與常識**
核心觀念：**socket 就是個檔案描述符**。連上線之後，收發資料就是 `read` / `write`，跟讀檔案一模一樣（直接沿用 L16）。

兩邊的流程：
```
伺服器:  socket() → bind() → listen() → accept() ⟲ 等待連線
客戶端:  socket() →                    connect()  → 發起連線
                          ↓
                    雙方 read/write
                          ↓
                       close()
```
`accept()` 會阻塞等待，並且回傳一個「新的」描述符。監聽用的 `listenfd` 和跟客戶溝通的 `connfd` 是兩個不同的東西：`listenfd` 從頭到尾只有一個，每來一個客戶就產生一個新的 `connfd`。

教授會要求用 `getaddrinfo`，不要用舊教材教的 `gethostbyname`——後者不支援 IPv6、而且不是執行緒安全的，`getaddrinfo` 把 IPv4/IPv6 的差異都封裝掉了。

HTTP 快速筆記（Proxy Lab 需要）：
請求：
```
GET http://example.com/index.html HTTP/1.0
Host: example.com
（空行 ← 標頭結束的標記,靠這個判斷讀完了）
```
回應：
```
HTTP/1.0 200 OK
Content-type: text/html
Content-length: 1234
（空行）
...實際內容...
```
Proxy Lab 的核心就是：讀客戶的請求 → 改寫一下 → 轉發給真的伺服器 → 把回應原封不動轉回去。

**📝 課後：細節與延伸重點**

兩個雷：
- 標頭用 `rio_readlineb` 逐行讀，直到讀到只有 `\r\n` 的空行。
- body 要用 `rio_readnb`，而且不能當成字串處理（可能含 `\0`，是二進位圖片之類的）。

## L23 — Concurrent Programming

**📘 課前：知識與常識**
這講在比較**三種讓程式同時做很多事的方式**，教授會逐一比較它們的取捨：

| 方式 | 優點 | 缺點 |
|---|---|---|
| 多行程 (fork) | 位址空間獨立，不會互相踩 | 開銷大，行程間溝通麻煩（要 IPC） |
| I/O 多工 (select) | 單一流程好除錯，完全控制 | 程式碼複雜，用不到多核心 |
| 多執行緒 (pthread) | 輕量、共享資料方便 | 共享 = 容易出 race，難除錯 |

必背：**執行緒共享什麼、不共享什麼**

| 共享 ✅ | 私有 ❌ |
|---|---|
| 全域變數、`static` 變數 | 執行緒 ID |
| 堆積（malloc 出來的） | 暫存器、程式計數器 |
| 程式碼、開啟的檔案描述符 | 堆疊（區域變數） |

**📝 課後：細節與延伸重點**

🔥 **陷阱：堆疊是「邏輯上」私有**
執行緒堆疊在記憶體裡並沒有被保護。如果 A 執行緒把區域變數的位址傳給 B，B 就能直接改它。
👉 考試問「執行緒的堆疊是共享的嗎」，標準答案是：「不是共享的，但也沒有被保護——拿得到位址就存取得到」。

🔥 **新手第一大坑：傳給執行緒的參數**
```c
for (i = 0; i < N; i++)
    pthread_create(&tid, NULL, thread, &i);    // ❌❌ 大錯特錯
```
所有執行緒拿到的都是「同一個 `i` 的位址」，而 `i` 一直在變。執行緒讀到的值完全不可預測（可能全都是 N）。
正解：每個執行緒配一份自己的資料：
```c
for (i = 0; i < N; i++) {
    int *p = malloc(sizeof(int));    // 每個一份
    *p = i;
    pthread_create(&tid, NULL, thread, p);     // 執行緒裡面記得 free(p)
}
```

記得 detach 或 join：執行緒結束後，資源不會自動回收，除非有人 `pthread_join` 它，或它自己 `pthread_detach`。長跑的伺服器忘了這件事 = 記憶體洩漏。Proxy Lab 每個連線開一個執行緒，一定要 detach。

## L24 — Synchronization: Basics

**📘 課前：知識與常識**
這講唯一的核心概念：**兩個執行緒同時改一個變數，會漏掉更新。因為 `cnt++` 不是一個動作，是三個。** 教授會用組語逐步拆解給你看：
```asm
movq  cnt(%rip), %rdx     # ① 讀
addq  $1, %rdx            # ② 加
movq  %rdx, cnt(%rip)     # ③ 寫
```
如果兩個執行緒都在 ① 讀到 5，各自加成 6，各自寫回 6 → 加了兩次，結果只多 1。關鍵詞：`cnt++` **不是原子操作 (not atomic)**，這句話要能脫口而出。

互斥鎖的用法：
```c
pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;

pthread_mutex_lock(&mutex);
cnt++;                        // ← 臨界區:一次只有一個執行緒能進來
pthread_mutex_unlock(&mutex);
```
CSAPP 用號誌 (semaphore) 版本教：
```c
sem_t mutex;
sem_init(&mutex, 0, 1);       // 初始值 1 = 互斥鎖
P(&mutex);   /* 臨界區 */   V(&mutex);
```
`P` = 想進去（值減 1，如果變負就等）、`V` = 出來了（值加 1，叫醒一個等待者）。記憶法：P = Proberen（測試/等待），V = Verhogen（增加/釋放）——荷蘭文，Dijkstra 取的。號誌不只能當鎖：初始值設成 N，就變成「最多同時 N 個人能進來」，可以用來限制連線數、限制緩衝區大小。

生產者-消費者（考試模板題，建議直接背）：
```c
sem_t mutex, slots, items;
sem_init(&mutex, 0, 1);       // 保護緩衝區
sem_init(&slots, 0, n);       // 還有幾個空位
sem_init(&items, 0, 0);       // 還有幾個東西

// 生產者                        // 消費者
P(&slots);   // 等空位            P(&items);   // 等有東西
P(&mutex);                       P(&mutex);
  放入資料                         取出資料
V(&mutex);                       V(&mutex);
V(&items);   // 多一個東西        V(&slots);   // 多一個空位
```

**📝 課後：細節與延伸重點**

👉 注意順序：一定是「先等資源 (slots/items)，再搶鎖 (mutex)」。反過來會死鎖！（拿著鎖去等資源，別人永遠進不來放資源給你）。這個順序是考題陷阱，也是實際寫 code 最容易顛倒的地方。

學長提醒：臨界區要盡量短。鎖住的範圍越大，併發度越低，你多開執行緒就白開了。

## L25 — Synchronization: Advanced

**📘 課前：知識與常識**
上一講解決了「怎麼保護共享變數」，這一講處理的是**用鎖之後新產生的問題**：死鎖，以及「這個函式在多執行緒下到底安不安全」。

死鎖 (Deadlock)：兩個執行緒各拿著對方要的鎖，互相等到天荒地老。
```c
// 執行緒 1              // 執行緒 2
P(&s0);                  P(&s1);      // ← 順序不同!
P(&s1);                  P(&s0);
```
唯一的黃金法則：
> **所有執行緒「取得多個鎖」時，順序必須完全一致。**
如果大家都是先 `s0` 再 `s1`，就永遠不會死鎖。這一句是這一講的全部精華。

執行緒安全 (Thread-Safe) 的四類不安全函式（教授會逐一舉例）：
1. 不保護共享變數的 → 加鎖就好。
2. 跨呼叫保留狀態的 → 例如 `rand()`（內部有 seed）→ 改用 `rand_r()`。
3. 回傳指向靜態變數指標的 → 例如 `ctime()`、`gethostbyname()` → 改用 `_r` 版本。
4. 呼叫了不安全函式的 → 傳染性。
👉 記憶訣竅：標準函式庫裡結尾有 `_r` 的版本（reentrant），就是為了執行緒安全而做的，看到 `_r` 就用它。

可重入 (Reentrant) vs 執行緒安全：
- 可重入 = 完全不用共享資料（所有狀態都在參數和區域變數裡）。
- 執行緒安全 = 用鎖保護了共享資料也算。
可重入是執行緒安全的「真子集」，而且更強（不用鎖，所以更快）。這個包含關係考試會考。

**📝 課後：細節與延伸重點**
讀者-寫者問題：多個讀者可以同時讀，但寫者要獨佔。要注意「飢餓」問題：如果一直有讀者來，寫者可能永遠等不到。所以有「讀者優先」和「寫者優先」兩種版本，這是這一講之外的延伸，考試較少細問，理解概念即可。

## L26 — Thread Level Parallelism

**📘 課前：知識與常識**
這講輕鬆，核心是 **Amdahl 定律**：它告訴你「加更多核心」到底能換到多少加速。
```
加速比 = 1 / ( (1-p) + p/k )

p = 可平行化的比例,k = 處理器數量
```
當 k → 無限大時，加速比的上限是 `1/(1-p)`。具體感受一下：
- 程式有 95% 可平行 → 就算你有無限多顆 CPU，最多也只能快 20 倍。
- 程式有 90% 可平行 → 上限只有 10 倍。
一句話結論：「不能平行的那 5%」才是你的天花板。加核心不是萬靈丹，優化序列部分才是關鍵。

併發 (Concurrency) vs 平行 (Parallelism)：
- 併發 = 邏輯上同時進行（單核心切換也算）。
- 平行 = 物理上真的同時執行（需要多核心）。
平行是併發的子集。這是面試常考的定義題。

**📝 課後：細節與延伸重點**

為什麼加了執行緒反而變慢？
- 同步開銷：鎖的爭用，執行緒都在排隊等鎖。
- **False Sharing（偽共享）** — 這個很陰險：兩個執行緒改不同的變數，但這兩個變數剛好在同一條 cache line 上 → 快取一直互相失效。
👉 解法：把不同執行緒用的資料「墊開」(padding)，讓它們落在不同的 cache line。
這題把 L12 快取和 L26 併發串起來了，是很漂亮的期末考題材料，屬於這一講之外的延伸理解。
